# プロキシ・SWG・ログ

フォワード／リバースプロキシ、クラウド型のセキュアWebゲートウェイ（SWG）、ログの使い方、FWのルール。令和7年度 B-1 問3 から作成。

## プロキシ

### フォワードプロキシとリバースプロキシの違いは？
- 段階: 基礎

| | フォワードプロキシ | リバースプロキシ |
|---|---|---|
| 置き場所 | 社内PCの出口側 | 公開するサーバの手前 |
| 代理するのは | **社内PC → 外のWebサイト** への通信 | **外の利用者 → 社内のサーバ** への通信 |
| 主な目的 | 宛先のブロック、アクセス履歴の記録、利用者認証 | サーバを直接さらさない、負荷分散、HTTPSの終端 |

R7 B-1 問3 では、SWGの導入でフォワードプロキシが不要になり、同じサーバを **社外PC（R-PC）から社内の業務用サーバに入るためのリバースプロキシ** に転用した。

### PCの通信をプロキシサーバ経由にする目的は？（本文の字句で2つ）
- 段階: 過去問
- 出典: R7 B-1 問3 設問1(2)
- 本文: ○

本文に書かれていたプロキシの機能から答える。
- **登録したFQDNやIPアドレス宛ての通信をブロックするため**
- **Webサイトへのアクセス履歴の確認のため**（または **利用者認証を行うため**）

> 「本文中の字句を用いて」→ 自分の知識で書かず、**本文の該当箇所の言葉をそのまま抜き出す**。プロキシの段落と syslog の段落に答えがあった。

### PACファイルとは？
- 段階: 知識
- 出典: R7 B-1 問3 ／ R6 B-1 問3

ブラウザに「**この宛先はプロキシ経由、この宛先は直接**」と指示する設定ファイル。中身はJavaScriptで書かれている。

R7 B-1 問3 の例：インターネット上のWebサイトはプロキシ経由、社内の業務用サーバとK社SaaSは直接。

PACファイルの置き場所をブラウザに自動で見つけさせる仕組みを **WPAD** という（R6 B-1 問3 で出題）。

## SWG（セキュアWebゲートウェイ）

### SWGサービスとは？
- 段階: 基礎

**プロキシとセキュリティ機能を、クラウドで提供するサービス。**

- PCにエージェントソフトを入れ、Web通信を全部 SWG 経由にする
- 社内のPCも、**社外に持ち出したPCも同じセキュリティポリシー** で守れる（テレワーク向き）
- 社内にプロキシサーバを置いて運用する手間がなくなる

主な機能（R7 B-1 問3 表2）：
- **ダイレクト通信**：登録した宛先は SWG を通さず直接通信
- **サイトブロック**：拒否リストの宛先をブロック
- **レピュテーション**：宛先の安全性を数値化して、しきい値以上のサイトだけ許可
- **マルウェア駆除**：パターン検査と、隔離環境（サンドボックス）での動作観察

### SWGがHTTPS通信の中身を調べるために、PCに入れておく証明書は？
- 段階: 過去問
- 出典: R7 B-1 問3 設問2(1)
- 本文: ◎

**SWGサービスのルート証明書。**

HTTPSは暗号化されているので、中身を調べるには SWG が一度復号する必要がある。SWG は自分で作ったサーバ証明書を PC に見せるため、その発行元である **SWGのルート証明書を、PCが信頼済みとして持っていないと** ブラウザが警告を出す。

> 「HTTPSの中身を検査する」機器が出てきたら →「**その機器のルート証明書をPCにインストール**」。プロキシでもUTMでも同じ。

### サンドボックスで遠隔操作型のマルウェアを動かすと、どこへの通信が観察される？
- 段階: 過去問
- 出典: R7 B-1 問3 設問2(2)
- 本文: ◎

**C&Cサーバ**（指令サーバ）。

遠隔操作型のマルウェアは、攻撃者が用意した C&C サーバに接続して命令を受け取る。隔離環境でファイルを実際に動かし、この通信が出たら「マルウェアだ」と判断できる。

### SaaS側で送信元IPを制限していると、SWG導入後に何を変える必要がある？
- 段階: 過去問
- 出典: R7 B-1 問3 設問3(4)
- 本文: ○

**アクセスを許可する送信元を、SWG-GIP（SWGが企業ごとに割り当てる固定のグローバルIP）に変更する。**

SWG経由にすると、SaaSから見た送信元は J社のIPではなく **SWGのIP** になる。許可リストを変えないと、SaaSに入れなくなる。

> 通信経路を変える話が出たら →「**送信元IPが変わる** → 相手のIP制限やFWのルールを直す」を必ず疑う。

### 社内PCから社内の業務用サーバへの通信を、SWGを通さず直接にする（直接接続リストに登録する）利点は？
- 段階: 過去問
- 出典: R7 B-1 問3 設問3(5)
- 本文: ○

通信経路が短くなることによる利点を書く。どれか1つでよい（10字以内）。
- **FWの負荷軽減**（回線やL3SWの負荷軽減も可）
- **RTTの短縮**（レスポンス改善）
- **可用性の向上**（インターネットやSWGが止まっても使える）

SWG経由だと、社内 → インターネット上のSWG → FW → 社内サーバ と、わざわざ外に出て戻ってくる遠回りになる。

> 「経路が短くなる利点」→ **負荷が減る・速くなる・止まりにくくなる** の3つから選ぶ。

## FWのルールと経路

### ステートフルパケットインスペクションのFWでは、戻りの通信の許可ルールは必要？
- 段階: 知識
- 出典: R7 B-1 問3 表1 注記

**不要。** 行きの通信を許可すれば、その **応答パケットは自動的に通る**。

だから FW のルールは「**通信を始める側** → 宛先」の向きだけ書けばいい。ルールを問われたら、どちらが通信を始めるかを考える。

### FWのルール表の空欄は、どうやって埋める？
- 段階: 過去問
- 出典: R7 B-1 問3 設問1(4)・(5)
- 本文: ○

**ポート番号から宛先を逆算する。**

R7の答え：
- DMZ → **syslogサーバ**（UDP/514 = syslog）
- プロキシサーバ → **認証サーバ**（UDP/1812 = RADIUS認証）
- 内部セグメント → プロキシサーバ：TCP/**10080**（本文に「TCP/10080で待ち受ける」とある）
- 内部セグメント → K社SaaS：TCP/**443**（HTTPS）

> ポート番号の暗記がそのまま点になる（「ポート番号」のカードを参照）。本文に独自の番号が書いてあれば、それが優先。

### フォワードプロキシをやめたときに削除するFWのルールは？
- 段階: 過去問
- 出典: R7 B-1 問3 設問3(1)
- 本文: △

**フォワードプロキシとしての通信だけ** を消す。R7では表1の項番 **2 と 7**。
- 項番2：プロキシサーバ → インターネット（TCP/80、443）
- 項番7：内部セグメント → プロキシサーバ（TCP/10080）

残すもの：プロキシ → 認証サーバ（リバースプロキシでも利用者認証に使う）、DMZ → syslog（ログ送信は続ける）。

> 機能を止めるときのルール削除 →「**その機能のためだけ** の通信か？ 他の用途でも使うか？」で仕分ける。

### SWG導入後、FWに追加する「PCがSWGに接続するための」許可ルールは？
- 段階: 過去問
- 出典: R7 B-1 問3 設問3(3)
- 本文: ○

| 送信元 | 宛先 | プロトコル／ポート |
|---|---|---|
| 内部セグメント（またはソフトE） | SWGサービス | **TCP/443** |

本文に「ソフトEはHTTPとHTTPSの通信を、SWGサービスの **TCP/443ポート宛てに** 中継する」とある。

### 社外PC（R-PC）から社内の業務用サーバへのアクセス経路は？
- 段階: 過去問
- 出典: R7 B-1 問3 設問3(2)
- 本文: △

**R-PC → ソフトE → SWG → FW → リバースプロキシ → FW → 業務用サーバ**
（記号では (B)、(A)、(H)、(I)、(E)、(I)、(K)）

ポイント：リバースプロキシはDMZにあるので、**FWを2回通る**（外 → DMZ で1回、DMZ → サーバセグメント で1回）。

> 経路を答える問題 → **DMZのサーバを経由するならFWを2回** 通る。図の線を1本ずつたどって、機器を飛ばさない。

## ログ

### 複数の機器の時刻を NTP で合わせる目的は？（ログ解析の観点）
- 段階: 過去問
- 出典: R7 B-1 問3 設問1(1)
- 本文: ◎

**複数機器のログを、時系列で確認するため。**

機器ごとに時計がずれていると、FWのログとプロキシのログを並べたときに、どちらが先に起きたかわからなくなる。

> 「NTPの目的は？」→ **ログを時系列で突き合わせるため**。

### FWのログで不正な通信を見つけた。送信元のPCを特定するには、どのログを見る？
- 段階: 過去問
- 出典: R7 B-1 問3 設問1(3)
- 本文: ○

**L3SWのDHCPリースログ。**

FWのログからわかるのは **IPアドレス** だけ。PCのIPアドレスはDHCPで配っているので日によって変わる。DHCPのリースログを見れば、「その時刻にそのIPアドレスを使っていたのはどのMACアドレス（どのPC）か」がわかる。

> 「IPアドレスからPCを特定」→ **DHCPのリースログ**（IPアドレスとMACアドレスの対応）。
