# ルーティング・冗長化

OSPF・BGP・VRRP と、ネットワークを止めずにルータを交換する手順。令和7年度 午後Ⅰ 問1 から作成。

## OSPF

### OSPFは何をするプロトコル？
- 段階: 基礎

社内ネットワークのルータ同士が **経路（どのネットワークへはどのルータに渡せばいいか）を自動で教え合う** ためのプロトコル。

- 各ルータが「自分は誰とどんなコストでつながっているか」を全員に配る
- 全員が同じ地図（リンクステートデータベース）を持ち、そこから **コストの合計が最小になる経路** を計算する
- 回線が切れると地図が更新され、自動で別の経路に切り替わる

人が経路を1本ずつ書く「スタティックルーティング」の反対で、こういう仕組みを **動的経路制御** という。

### OSPFの「コスト」とは？ 経路はどう選ばれる？
- 段階: 基礎

コスト ＝ インタフェースごとに設定する「その回線を通る重さ」。

- 宛先までに通る **出力インタフェースのコストを足し算** して、合計が **小さい経路** を使う
- 合計が同じ経路が複数あれば、両方に振り分けることもできる（等コストマルチパス）

R7 午後Ⅰ 問1 の設定例：広域イーサ網の接続口が **100**、IPsec VPN の接続口が **1000**
→ 普段は安い広域イーサ網を使い、広域イーサ網が使えないときだけ IPsec VPN を使う。

### OSPFのインタフェースコストの最大値は？
- 段階: 知識

**65535**。

あるルータに通信を通したくないときは、そのルータのインタフェースのコストを最大値（65535）のような十分大きな値にする。そうすると、そこを通る経路の合計コストが大きくなり、別の経路が選ばれる。

### エリアID 0.0.0.0 のエリアを何という？
- 段階: 知識
- 出典: R7 午後Ⅰ 問1 設問1(1)a
- 本文: ◎

**バックボーンエリア**（エリア0）。

OSPFは大きなネットワークをエリアに分けられる。他のエリアは必ずバックボーンエリアにつながる必要がある。小さなネットワークならバックボーンエリアだけで構成することも多い。

### OSPFルータを識別するIDを何という？ なぜループバックアドレスを使う？
- 段階: 知識
- 出典: R7 午後Ⅰ 問1 設問1(1)b
- 本文: ◎

**ルータID**。IPv4アドレスと同じ形式（32ビット）で書く。

ループバックインタフェースは **物理的なケーブルや口に依存しない仮想のインタフェース** なので、どこかの物理インタフェースが故障してもダウンしない。だからルータIDが変わらず安定する。

### パッシブインタフェースとは？
- 段階: 知識

OSPFのやり取り（Helloパケット）を **送受信しない** ように設定したインタフェース。

- そのインタフェースの先にいる相手とは隣接関係を作らない（経路を教え合わない）
- ただし、**そのインタフェースのネットワーク自体は経路として他のルータに広告される**

PCがつながるだけのセグメントなど、ルータがいない場所に設定する。余計なパケットを流さず、不正なルータとの隣接も防げる。

### OSPFで「隣接関係（ネイバー）」はどうやって作られる？
- 段階: 知識

ルータ同士が **Helloパケット** を定期的に送り合って、相手を見つけて隣接関係を作る。

- Hello間隔：10秒（イーサネットの標準値）
- Dead間隔：40秒。この間Helloが届かなければ「相手が落ちた」と判断して経路を計算し直す
- 隣接関係ができた相手とだけ、経路の情報（LSA）を交換する

### OSPFのネイバー認証で、どんな問題を防げる？
- 段階: 過去問
- 出典: R7 午後Ⅰ 問1 設問1(2)
- 本文: ◎

**不正なOSPFルータと隣接関係になり、経路交換してしまう問題。**

認証キーが一致しない相手とは隣接関係を作らない。勝手につながれたルータが偽の経路を流して、通信を横取りしたり止めたりするのを防ぐ。

> 「〇〇認証で何を防ぐ？」→「不正な相手と△△してしまうこと」と、**認証がなかったら起きる事故** を答える。

### 「再配布」とは？ 相互再配布で気をつけることは？
- 段階: 知識

**再配布** ＝ あるルーティングプロトコルで覚えた経路を、別のプロトコルに流し込むこと。

例（R7 午後Ⅰ 問1）：取引先のクラウドサービスから BGP で受け取った経路を OSPF に流して社内に知らせる。逆に OSPF の社内経路を BGP に流して、クラウド側に知らせる。

両方向に流す **相互再配布** では、流した経路が別のルータ経由で戻ってきて **経路のループ** が起きることがある。そのため、プレフィックスリストなどで **経路フィルタリング** をかけて防ぐ。

### OSPFでデフォルトルートを配る、とはどういうこと？
- 段階: 知識

インターネットにつながる機器（R7 午後Ⅰ 問1 ではFW）が「知らない宛先は全部こっちに送って」という経路（0.0.0.0/0）をOSPFで社内全体に配ること。

各ルータに1台ずつインターネット向けの経路を手で書かなくても、OSPFで自動的に行き渡る。

## BGP

### BGPは何をするプロトコル？ OSPFとの違いは？
- 段階: 基礎

**組織と組織の間（AS間）で経路を交換する** プロトコル。インターネットの経路制御はBGPで成り立っている。

| | OSPF | BGP |
|---|---|---|
| 使う場所 | 組織の中 | 組織と組織の間 |
| 経路の選び方 | コストの合計が小さい経路 | 属性（AS_PATHなど）で選ぶ。ポリシーで細かく制御できる |
| 通信 | IP（プロトコル番号89） | TCP 179番 |

**AS**（自律システム）＝ 1つの組織が管理するネットワークのまとまり。AS番号で区別する。

- **eBGP**：違うAS同士の接続（例：自社と、クラウドサービスの事業者）
- **iBGP**：同じAS内のルータ同士の接続

### BGPの AS_PATH とは？ どちらの経路が優先される？
- 段階: 知識

AS_PATH ＝ その経路が **どのASを経由して届いたか** の一覧。

BGPは基本的に **AS_PATHが短い（経由するASが少ない）経路を優先** する。

### AS_PATHプリペンドとは？ 何のために使う？
- 段階: 知識

経路を広告するときに **自分のAS番号をわざと何回も付け足して、AS_PATHを長く見せる** こと。

→ 相手から見ると「遠回りな経路」に見えるので選ばれにくくなる。
→ **相手から自分に入ってくる通信が、どのルータを通るかを制御できる。**

使い方：普段使いたい回線では付け足さず、予備の回線では付け足す。

### BGPでつなぐルータが2台ある。片方をメイン、もう片方を予備にしたい。予備のルータが広告するAS_PATHの長さは、メインと比べてどうする？
- 段階: 過去問
- 出典: R7 午後Ⅰ 問1 設問1(3)
- 本文: ◎
- 状況: A社は、C社のクラウドサービス（SaaS）とBGPでつながっている。つなぐルータは2台で、普段はR30を使い、R30が使えないときだけR31を使いたい。

**長くする。**

AS_PATHが短い経路が優先されるので、予備のルータ（R31）側をプリペンドで長くすれば、相手（C社のSaaS）は普段メインのルータ（R30）側を選ぶ。

> BGPで「メイン／予備」を作る問題 → **予備側を不利にする**（AS_PATHを長く、など）と答える。

### BGPで経路を選ぶときの主な属性（優先順）は？
- 段階: 知識

ざっくりこの順で比べる。

1. **LOCAL_PREF**：**大きい** ほど優先。自分のAS内で共有し、**自分から出ていく通信** の出口を決める
2. **AS_PATH**：**短い** ほど優先
3. **MED**：**小さい** ほど優先。隣のASに「こっちから入ってきてほしい」と伝える

覚え方：出ていく方向は LOCAL_PREF、入ってくる方向は AS_PATHプリペンド か MED。

## VRRP

### VRRPは何をするプロトコル？
- 段階: 基礎

**PCのデフォルトゲートウェイを冗長化する** プロトコル。

- 2台以上のルータ（またはL3スイッチ）で、**1台の仮想ルータ**（仮想IPアドレス・仮想MACアドレス）を作る
- PCのデフォルトゲートウェイには **仮想IPアドレス** を設定しておく
- 普段は **マスター** が仮想ルータとして通信を中継し、他は **バックアップ** として待機
- マスターが故障すると、バックアップが自動でマスターになる。PC側の設定は変えなくていい

### VRRPで、PCに設定するデフォルトルートのネクストホップに相当するものは？
- 段階: 過去問
- 出典: R7 午後Ⅰ 問1 設問1(1)c
- 本文: ◎

**デフォルトゲートウェイ。**

VRRPが冗長化するのはデフォルトゲートウェイ、とセットで覚える。

### VRRPのマスターはどう決まる？ バックアップはどうやって故障に気づく？
- 段階: 知識

- **プライオリティ（優先度）が大きい** ルータがマスターになる（R7 午後Ⅰ 問1 では、東京支社の2台のルータを 105 と 100 に設定 → 105 のほうがマスター）
- マスターは **VRRPアドバタイズメント** を定期的にマルチキャストで送る
- バックアップは、アドバタイズメントが一定時間届かなければ「マスターが落ちた」と判断してマスターになる

### VRRPの仮想MACアドレスの形式は？
- 段階: 知識

**00-00-5E-00-01-{VRID}**（VRIDは仮想ルータの番号）。

マスターが入れ替わっても仮想MACアドレスは変わらないので、PCは同じ宛先MACのまま通信を続けられる。

### VRRPの「プリエンプト」とは？
- 段階: 知識

プライオリティが高いルータが復帰したときに、**今のマスターからマスターを奪い返す** 動作。

- プリエンプトあり：高いほうが復帰したら、すぐマスターに戻る
- プリエンプトなし：復帰しても、今のマスターがそのまま続ける

### プリエンプトディレイで一定時間待つのは、ルータがどんな状態になるのを待つため？
- 段階: 過去問
- 出典: R7 午後Ⅰ 問1 設問1(4)
- 本文: ○

**OSPFの経路情報が収束した状態。**

再起動した直後のルータは、まだOSPFで経路を覚えきれていない。その状態ですぐマスターになると、PCからの通信を受け取っても転送先がわからず通信が途切れる。だから経路がそろうまでマスターになるのを待つ。

> 「切り替えを待つ理由」→ **切り替え先の準備（経路の学習など）がまだ整っていないから**。

### VRRPのトラッキングとは？
- 段階: 知識

マスターの **上流側のインタフェース（WAN側など）を監視** して、ダウンしたら自分のプライオリティを下げる機能。

LAN側は生きていても上流が切れていると、マスターのままでは通信が外に出られない。プライオリティを下げてバックアップにマスターを譲ることで、通信を正しい経路に切り替える。

## ネットワークを止めずに機器を交換する

### 機器を止めずに交換する基本の流れは？
- 段階: 基礎

R7 午後Ⅰ 問1 のルータ交換手順を一般化するとこうなる。

1. **迂回**：設定変更（OSPFコストを上げるなど）で、通信を交換する機器から逃がす
2. **確認**：通信が迂回先で正常に流れているか確かめる
3. **切り離し**：交換する機器のインタフェースを閉塞する
4. **交換**：電源を切り、ケーブルを抜き、新しい機器に入れ替える
5. **設定確認**：新しい機器の設定が想定どおりか比べる
6. **接続と確認**：ケーブルをつなぎ、閉塞を解除して、新しい機器から隣の機器にpingする
7. **切り戻し**：迂回をやめて通信を新しい機器に戻し、正常に流れるか確かめる

作業中は、PCから継続してpingを打ち続けて、通信が途切れていないかを見張る。

### ルータを交換する間、通信をもう1台のルータに迂回させたい。交換するルータのインタフェースのOSPFコストをどうする？
- 段階: 過去問
- 出典: R7 午後Ⅰ 問1 設問2(2)
- 本文: ◎
- 状況: A社は、大阪本社・東京支社・C社のデータセンターを、普段使う「広域イーサ網」と予備の「IPsec VPN」の2種類の回線でつないでいる。大阪本社には他拠点とつなぐルータが2台あり、R10が広域イーサ網側、R11がIPsec VPN側。このR10を、通信を止めずに新しい機種に交換したい。

**65535 といった十分大きな値に変更する。**

交換するルータ（R10）を通る経路の合計コストが大きくなり、OSPFが自動的にもう1台（R11）側の経路を選ぶ。

> OSPFで「この機器を通さない」→ **コストを最大値（65535）に** と答える。

### ルータを交換する。電源を切る前に、全ての物理インタフェースを閉塞（使えない状態に）するのはなぜ？
- 段階: 過去問
- 出典: R7 午後Ⅰ 問1 設問2(3)
- 本文: ○
- 状況: A社は、大阪本社・東京支社・C社のデータセンターを、普段使う「広域イーサ網」と予備の「IPsec VPN」の2種類の回線でつないでいる。大阪本社には他拠点とつなぐルータが2台あり、R10が広域イーサ網側、R11がIPsec VPN側。このR10を、通信を止めずに新しい機種に交換したい。 手順は「通信を迂回 → インタフェースを閉塞 → 電源オフ → 交換」の順。

**物理インタフェースの閉塞のほうが、素早く切り戻せるから。**

切り離した結果、もし業務に影響が出ても、閉塞を解除するだけですぐ元に戻せる。いきなり電源を切ってしまうと、戻すには電源を入れて起動を待たなければならない。

> 作業手順の「なぜこの順番？」→ **何かあったときにすぐ戻せる（切り戻しやすい）から** が定番の答え。

### ルータの交換作業中に業務影響がないか、PCからpingを打ち続けて確かめる。宛先はどこにする？
- 段階: 過去問
- 出典: R7 午後Ⅰ 問1 設問2(1)
- 本文: △
- 状況: A社は、大阪本社・東京支社・C社のデータセンターを、普段使う「広域イーサ網」と予備の「IPsec VPN」の2種類の回線でつないでいる。大阪本社には他拠点とつなぐルータが2台あり、R10が広域イーサ網側、R11がIPsec VPN側。このR10を、通信を止めずに新しい機種に交換したい。 宛先の候補は「インターネット」「大阪本社のサーバセグメント」「C社のSaaS」の3つ。

**交換するルータ（R10）を経由する通信の宛先。** 図で拠点ごとに経路をたどって選ぶ。

図のつながり方（要点）：
- 大阪本社：PC → L3スイッチ（L3SW10）。インターネットへは L3SW10 → FW10 で出る。サーバセグメントも L3SW10 に直結
- 広域イーサ網（普段使う）：大阪の **R10**、東京の **R20**、C社データセンターの **R30** がつながる
- IPsec VPN（予備）：大阪の **R11**、東京の **R21**、C社データセンターの **R31** がつながる
- 東京支社：PC → R20／R21。C社SaaS：R30／R31 の奥

答え：
- 大阪本社のPCから → **C社のSaaS**（大阪 → R10 → 広域イーサ網 → C社）
- 東京支社のPCから → **インターネット** と **大阪本社のサーバセグメント**（東京 → 広域イーサ網 → R10 → 大阪）

大阪からインターネットやサーバへの通信は、R10を通らずにL3SW10から直接行けるので対象外。東京からC社のSaaSも、広域イーサ網で直接C社に行けるので対象外。

> 「どこにpingを打つ？」→ **その機器を通る通信だけ** を、図の線をたどって選ぶ。同じ拠点の中で完結する通信は、WAN側のルータを通らない。

### 交換した新しいルータをつないだ直後、そのルータ自身からどこにpingを打つ？（機器名で4つ）
- 段階: 過去問
- 出典: R7 午後Ⅰ 問1 設問2(5)
- 本文: △
- 状況: A社は、大阪本社・東京支社・C社のデータセンターを、普段使う「広域イーサ網」と予備の「IPsec VPN」の2種類の回線でつないでいる。大阪本社には他拠点とつなぐルータが2台あり、R10が広域イーサ網側、R11がIPsec VPN側。このR10を、通信を止めずに新しい機種に交換したい。 新しいR10にケーブルをつなぎ、インタフェースの閉塞を解除したところ。まだ通信はR11側に迂回させたまま。

**L3SW10、R11、R20、R30**（新しいR10と直接つながっている機器すべて）。

図のつながり方（要点）：
- 大阪本社：PC → L3スイッチ（L3SW10）。インターネットへは L3SW10 → FW10 で出る。サーバセグメントも L3SW10 に直結
- 広域イーサ網（普段使う）：大阪の **R10**、東京の **R20**、C社データセンターの **R30** がつながる
- IPsec VPN（予備）：大阪の **R11**、東京の **R21**、C社データセンターの **R31** がつながる
- 東京支社：PC → R20／R21。C社SaaS：R30／R31 の奥

まだ通信を戻す前の段階なので、新しいR10の **全インタフェースが隣の機器と正しく通信できるか** を確かめる。
- 大阪本社側のセグメント → 本社のL3スイッチ（L3SW10）と、同じセグメントにいるもう1台のルータ（R11）
- 広域イーサ網側 → 東京支社のルータ（R20）と、C社データセンターのルータ（R30）

> 交換後の確認 →「**全インタフェース**で、**直接つながる相手全部**」にping。
